Etapa 0

Visão geral: o que o grupo vai construir

Até aqui, a estufa do Sr. João existia só no papel ou dentro do Node-RED. Agora ela ganha um “cérebro” de verdade: um ESP32 com sensores e atuadores, que conversa pela internet com um painel. Tudo simulado, sem precisar comprar nenhuma peça.

ESP32 no Wokwi Broker HiveMQ Painel Node-RED
Wokwi
Simulador de eletrônica no navegador. Lá montamos o circuito e rodamos o código do ESP32.
ESP32
A placa (microcontrolador) com Wi-Fi. Ela lê os sensores e liga ou desliga os atuadores.
MicroPython
A linguagem que vamos usar no ESP32: é o Python, em versão para placas pequenas.
HiveMQ
O broker MQTT, o “carteiro” na internet: recebe as mensagens do ESP32 e entrega para o Node-RED, e vice-versa. Usaremos o broker público e gratuito broker.hivemq.com.
Node-RED
Onde fica o painel (dashboard) com medidores, gráfico e botões. Pode rodar no FlowFuse (na nuvem, recomendado) ou no computador.

Primeiro passo de todos: o nome do grupo

O broker broker.hivemq.com é público: o mundo inteiro usa o mesmo. Se dois grupos usarem o mesmo tópico, um vai ligar a lâmpada do outro! Por isso, cada grupo escolhe um nome único, que entra em todos os tópicos.

Digite aqui e todos os códigos desta página se ajustam sozinhos. O nome fica salvo neste navegador; em outro computador, digite de novo, exatamente igual.
Atenção

Como o broker é público, qualquer pessoa que souber o tópico consegue ler as mensagens. Nunca envie dados pessoais, senhas ou nomes completos pelo MQTT.

    Por que o resistor?

    Ele limita a corrente que passa pelo LED. Sem ele, um LED de verdade queimaria. Os pinos do ESP32 trabalham com 3,3 V, e o resistor de 220 Ω deixa passar só o suficiente para acender.

Etapa 2 1º ponto

Programando o ESP32: Wi-Fi e MQTT

Confira se o nome do grupo foi digitado na Etapa 0: a linha GRUPO = "GRUPO_AQUI" do código abaixo tem que mostrar o nome de vocês, e não GRUPO_AQUI.

  1. Cole o código no main.py

    No Wokwi, clique na aba main.py, apague tudo e cole:

    main.py (MicroPython)
    # =========================================================
#  Estufa do Sr. João - ESP32 + Wi-Fi + MQTT (MicroPython)
# =========================================================
import network
import time
import ujson
import dht
from machine import Pin, ADC
from umqtt.simple import MQTTClient

# ---------- 1) CONFIGURAÇÕES ----------
WIFI_SSID  = "Wokwi-GUEST"        # rede Wi-Fi do simulador
WIFI_SENHA = ""                   # o Wokwi-GUEST não tem senha

BROKER    = "broker.hivemq.com"   # broker MQTT público da HiveMQ
PORTA     = 1883
GRUPO     = "GRUPO_AQUI"          # nome único do seu grupo
CLIENT_ID = "esp32-" + GRUPO

BASE            = "estufa-joao/" + GRUPO
TOPICO_SENSORES = BASE + "/sensores"     # ESP32 -> Node-RED
TOPICO_ESTADO   = BASE + "/estado"       # ESP32 -> Node-RED
TOPICO_COMANDOS = BASE + "/comandos/#"   # Node-RED -> ESP32

INTERVALO_MS = 5000               # envia os sensores a cada 5 segundos

# ---------- 2) SENSORES E ATUADORES ----------
sensor_ar = dht.DHT22(Pin(15))           # temperatura e umidade do ar
sensor_solo = ADC(Pin(34))               # potenciômetro = umidade do solo
sensor_solo.atten(ADC.ATTN_11DB)         # permite ler de 0 a 3,3 V

atuadores = {
    "ventilador": Pin(26, Pin.OUT),      # LED azul
    "bomba":      Pin(27, Pin.OUT),      # relé da bomba d'água
    "lampada":    Pin(25, Pin.OUT),      # LED amarelo
}

# ---------- 3) WI-FI ----------
def conectar_wifi():
    print("Conectando ao Wi-Fi", end="")
    wifi = network.WLAN(network.STA_IF)  # cria o objeto Wi-Fi
    wifi.active(True)                    # liga o Wi-Fi
    wifi.connect(WIFI_SSID, WIFI_SENHA)  # conecta na rede
    while not wifi.isconnected():
        print(".", end="")
        time.sleep(0.3)
    print(" conectado! IP:", wifi.ifconfig()[0])

# ---------- 4) MQTT ----------
def publicar_estado():
    estado = {}
    for nome in atuadores:
        estado[nome] = "ON" if atuadores[nome].value() == 1 else "OFF"
    cliente.publish(TOPICO_ESTADO, ujson.dumps(estado))
    print("Estado publicado:", estado)

def ao_receber_comando(topico, mensagem):
    topico = topico.decode()
    comando = mensagem.decode().strip().upper()
    nome = topico.split("/")[-1]         # ".../comandos/bomba" -> "bomba"
    print("Comando recebido:", nome, "=", comando)
    if nome in atuadores:
        if comando == "ON":
            atuadores[nome].value(1)
        elif comando == "OFF":
            atuadores[nome].value(0)
        publicar_estado()

def conectar_mqtt():
    print("Conectando ao broker", BROKER, "...")
    c = MQTTClient(CLIENT_ID, BROKER, port=PORTA, keepalive=60)  # cria o cliente
    c.set_callback(ao_receber_comando)   # função chamada quando chega comando
    c.connect()                          # conecta no broker
    c.subscribe(TOPICO_COMANDOS)         # assina os comandos dos atuadores
    print("MQTT conectado! Ouvindo:", TOPICO_COMANDOS)
    return c

# ---------- 5) PROGRAMA PRINCIPAL ----------
conectar_wifi()
cliente = conectar_mqtt()
publicar_estado()

ultimo_envio = time.ticks_add(time.ticks_ms(), -INTERVALO_MS)  # já envia na 1ª volta
while True:
    try:
        cliente.check_msg()              # chegou comando? (não trava o programa)

        if time.ticks_diff(time.ticks_ms(), ultimo_envio) >= INTERVALO_MS:
            ultimo_envio = time.ticks_ms()
            sensor_ar.measure()
            dados = {
                "temperatura": sensor_ar.temperature(),
                "umidade": sensor_ar.humidity(),
                "solo": round(sensor_solo.read() * 100 / 4095),
            }
            cliente.publish(TOPICO_SENSORES, ujson.dumps(dados))
            print("Sensores publicados:", dados)

    except OSError as erro:
        print("Conexão perdida:", erro, "- reconectando...")
        time.sleep(2)
        cliente = conectar_mqtt()

    time.sleep(0.1)

  2. Entenda as partes que valem nota

    O professor vai procurar exatamente estes comandos. Saibam apontar cada um no vídeo:

    O enunciado pedeLinha no códigoO que faz
    Criar objeto Wi-Fi com network.WLANwifi = network.WLAN(network.STA_IF)Cria o Wi-Fi no modo “estação” (o ESP32 entra numa rede, como um celular).
    Ativar com active()wifi.active(True)Liga o rádio Wi-Fi.
    Conectar com connect()wifi.connect(WIFI_SSID, WIFI_SENHA)Entra na rede Wokwi-GUEST, a rede virtual do simulador, que não tem senha.
    Cliente umqtt.simple.MQTTClientMQTTClient(CLIENT_ID, BROKER, port=PORTA, ...)Cria o “cliente” que vai conversar com o broker. O CLIENT_ID precisa ser único no broker.
    Conectar com connect()c.connect()Conecta no broker.hivemq.com, porta 1883.
    Enviar dados com publish()cliente.publish(TOPICO_SENSORES, ...)Publica os sensores em JSON a cada 5 segundos.
    Ouvir comandos com subscribe()c.subscribe(TOPICO_COMANDOS)Assina comandos/#. O # pega os três atuadores de uma vez.

    Outras peças importantes:

    • set_callback(ao_receber_comando): diz qual função rodar quando chegar uma mensagem. Ela descobre qual atuador é pelo fim do tópico e liga (ON) ou desliga (OFF).
    • check_msg(): confere se chegou comando sem travar o programa. Por isso o laço roda a cada 0,1 s, mas os sensores só são enviados a cada 5 s.
    • try / except OSError: se a conexão cair, o ESP32 reconecta sozinho em vez de parar.

Etapa 3 1º ponto

Testando o MQTT antes do painel

Antes de montar o painel, vamos conferir se o ESP32 está mesmo conversando com o broker. Para isso usamos uma página da própria HiveMQ que funciona como um “cliente MQTT” dentro do navegador: ela consegue ver o que o ESP32 manda e mandar comandos para ele.

Se algo der errado mais tarde, é este teste que mostra se o problema está no ESP32 ou no Node-RED.

Conheça a tela

A página tem quatro áreas. O desenho abaixo é uma versão simplificada:

A ordem importa

Primeiro conectar (bolinha verde), depois assinar, depois publicar. Se tentar assinar com a bolinha vermelha, nada acontece.

Passo a passo

  1. Deixe o Wokwi rodando

    Na aba do Wokwi, a simulação precisa estar ligada (▶) e o monitor serial mostrando Sensores publicados. Não feche essa aba.

  2. Abra o cliente da HiveMQ em outra aba

    Abra uma nova aba do navegador (Ctrl + T) e acesse:

    Endereço do navegador
    https://www.hivemq.com/demos/websocket-client/

  3. Arrume o Host (área A)

    O campo Host já vem preenchido com outro endereço (como mqtt-dashboard.com). Apague e escreva:

    Host
    broker.hivemq.com

    Deixe a Port em 8000 e não mexa nos outros campos.

    Por que 8000 e não 1883 como no ESP32? O navegador não fala MQTT “puro”: ele usa uma porta especial (WebSocket). O broker é o mesmo, só a porta de entrada muda.

  4. Clique em Connect

    Clique no botão azul Connect e espere a bolinha ao lado de Connection ficar verde. O botão muda para Disconnect. Pronto, você está conectado.

  5. Assine os tópicos do grupo (área B)

    Em Subscriptions, clique em Add New Topic Subscription. Abre uma janelinha. No campo Topic, apague o que tiver e cole:

    Topic
    estufa-joao/GRUPO_AQUI/#

    Não precisa mexer em Color nem em QoS. Clique em Subscribe. O tópico aparece listado em Subscriptions.

    O # no final quer dizer “tudo o que começa com estufa-joao/GRUPO_AQUI/”: sensores, estado e comandos.

  6. Veja os dados chegando (área D)

    Clique na setinha ▾ ao lado de Messages para abrir a área. A cada 5 segundos aparece uma mensagem com o tópico .../sensores e os valores, por exemplo {"temperatura": 24.0, "umidade": 40.0, "solo": 42}.

    Mexa no DHT22 ou no potenciômetro no Wokwi e veja os números mudarem aqui. ✅ Isso prova que o publish() do ESP32 funciona.

  7. Mande um comando para o ESP32 (área C)

    Clique na setinha ▾ ao lado de Publish para abrir a área. No campo Topic, cole:

    Topic
    estufa-joao/GRUPO_AQUI/comandos/lampada

    No campo grande Message, escreva ON e clique em Publish.

    Volte para a aba do Wokwi: o LED amarelo acendeu e o monitor serial mostra Comando recebido: lampada = ON. ✅ Isso prova que o subscribe() do ESP32 funciona.

    Para apagar, publique OFF no mesmo tópico. Teste também trocando o final do tópico por ventilador (LED azul) e bomba (relé).

Não funcionou?

A bolinha não fica verde

Confira se o Host está exatamente broker.hivemq.com e a Port 8000. Algumas redes de escola bloqueiam essa porta: tente pelo celular, roteando a internet, ou faça o teste em casa.

Conectou, mas não chega nada em Messages

O tópico assinado não bate com o do código. Compare letra por letra com a linha MQTT conectado! Ouvindo: … que aparece no começo do monitor serial do Wokwi, e com o GRUPO = "…" do main.py. Confira também se a área Messages está aberta (setinha ▾).

Publiquei ON e o LED não acendeu

Confira o tópico (tem que terminar em /comandos/lampada) e se a mensagem é só ON, sem espaços. Veja no monitor serial se aparece Comando recebido: se aparece, o problema é a ligação do LED (perna A no resistor, C no GND).

Dica para o vídeo

Este teste é ótimo para mostrar no vídeo: deixem a HiveMQ e o Wokwi lado a lado e mostrem a mensagem saindo de um lado e chegando do outro.

    • Nome: HiveMQ público
    • Servidor: broker.hivemq.com   Porta: 1883

    Clique em Adicionar. De volta ao mqtt in: Tópico estufa-joao/GRUPO_AQUI/sensores, Saída um objeto JSON analisado, nome Sensores do ESP32. Ligue um debug na saída e clique em Implementar. Com o Wokwi rodando, os dados aparecem na aba 🐞 e o nó mostra conectado em verde.

  3. Separe os três valores (function com 3 saídas)

    Cada medidor precisa de um número só, mas a mensagem traz três. Arraste um function, ligue depois do mqtt in, nome Separa os sensores. Na aba Configuração (Setup), mude Saídas para 3. Na aba Ao receber mensagem, cole:

    Código do nó function
    // Chega do ESP32: { temperatura: 26.5, umidade: 55, solo: 40 }
let d = msg.payload;
return [
    { payload: d.temperatura, topic: "Temperatura (°C)" },
    { payload: d.umidade,     topic: "Umidade do ar (%)" },
    { payload: d.solo,        topic: "Umidade do solo (%)" }
];

    Saída 1 = temperatura, saída 2 = umidade do ar, saída 3 = umidade do solo. O topic vira o nome da linha no gráfico.

  4. Coloque três medidores (gauge)

    Arraste três nós gauge e ligue um em cada saída do function. No primeiro, em Group escolha Add new ui-group…, clique no lápis ✏️, dê o nome Sensores e clique em Adicionar (se pedir Page e UI, faça o mesmo: lápis e Adicionar). Configure:

    GaugeLabelUnitsRange
    Saída 1Temperatura°C0 a 50
    Saída 2Umidade do ar%0 a 100
    Saída 3Umidade do solo%0 a 100

    Nos outros dois, escolham o mesmo grupo Sensores.

  5. Coloque o gráfico (chart)

    Arraste um chart, crie um grupo novo chamado Histórico, Label Histórico, tipo Line. Ligue nele as saídas 1 e 2 do function (uma saída pode ter vários fios). Cada valor vira uma linha com o nome que está no topic.

  6. Crie os botões dos atuadores (switch + mqtt out)

    Arraste três nós switch (o azul, da categoria dashboard 2) e crie um grupo chamado Controles. Em cada um: Label com o nome do atuador, On Payload texto ON, Off Payload texto OFF. Deixe desmarcada a opção de repassar a mensagem de entrada (Pass through).

    Depois de cada switch, ligue um mqtt out com o servidor HiveMQ público e o tópico:

    Switch (Label)Tópico do mqtt out
    Ventiladorestufa-joao/GRUPO_AQUI/comandos/ventilador
    Bomba d’águaestufa-joao/GRUPO_AQUI/comandos/bomba
    Lâmpadaestufa-joao/GRUPO_AQUI/comandos/lampada

  7. Mostre o estado real nos botões (boa prática)

    E se o ESP32 reiniciar, ou alguém mandar um comando pelo cliente da HiveMQ? O botão ficaria mostrando a coisa errada. Para resolver, o painel escuta o tópico estado que o ESP32 publica:

    Arraste outro mqtt in: tópico estufa-joao/GRUPO_AQUI/estado, saída objeto JSON analisado. Ligue um function com 3 saídas, nome Atualiza os botões, com o código abaixo, e ligue cada saída na entrada do switch correspondente (1 = Ventilador, 2 = Bomba, 3 = Lâmpada).

    Código do nó function
    // Chega do ESP32: { ventilador: "ON", bomba: "OFF", lampada: "OFF" }
// Atualiza os botões do painel com o estado REAL dos atuadores
let e = msg.payload;
return [
    { payload: e.ventilador },
    { payload: e.bomba },
    { payload: e.lampada }
];

    Como a opção Pass through está desmarcada, o switch só muda a posição e não manda o comando de novo. Assim não se forma um “loop”.

  8. Implemente e abra o painel

    Clique em Implementar. Para abrir o painel:

    • No FlowFuse: na página da instância, clique no botão Dashboard (pela setinha dele, Open Direct URL abre numa aba própria). Esse endereço é o link do painel para entregar.
    • No Node-RED local: acrescente /dashboard no fim do endereço do editor, por exemplo http://127.0.0.1:1880/dashboard.

Etapa 5

Teste final e depuração

Com o Wokwi rodando numa aba e o painel aberto em outra (de preferência lado a lado), confiram um por um:

  1. Sensores no painel

    Mudem a temperatura no DHT22 e girem o potenciômetro. Em até 5 segundos, os medidores e o gráfico acompanham.

  2. Botões no ESP32

    Liguem e desliguem cada botão do painel. O LED azul (ventilador), o relé (bomba) e o LED amarelo (lâmpada) obedecem, e o monitor serial mostra o Comando recebido.

  3. Estado de volta no painel

    Mandem ON pelo cliente da HiveMQ (Etapa 3). O botão correspondente no painel deve mudar sozinho.

Deu problema? Procure o sintoma

O monitor serial fica só em “Conectando ao Wi-Fi.....”

Confiram se está escrito exatamente Wokwi-GUEST (com letras maiúsculas e o hífen) e a senha vazia "". Parem e rodem de novo a simulação.

“ImportError: no module named 'umqtt'” ou erro logo na primeira linha

O projeto não é MicroPython. Criem um novo pelo link da Etapa 1 e colem o circuito e o código nele.

“MQTTException: 2” ou o ESP32 fica reconectando sem parar

O CLIENT_ID já está em uso. Isso acontece quando a mesma simulação está aberta em duas abas ou dois computadores do grupo: o broker derruba um para aceitar o outro. Deixem o Wokwi rodando em um só lugar. Se ainda assim continuar, troquem o nome do grupo por algo mais único.

“OSError: [Errno 116] ETIMEDOUT” na leitura do DHT22

O fio de dados do DHT22 (SDA) não está no pino 15, ou falta VCC/GND. Confiram a tabela de ligações.

Os dados aparecem no cliente da HiveMQ, mas não no Node-RED

O problema está no Node-RED: (1) o tópico do mqtt in está diferente, letra por letra, do que o ESP32 usa; (2) o servidor não é broker.hivemq.com porta 1883; (3) faltou clicar em Implementar. Olhem se embaixo do mqtt in aparece conectado.

A aba 🐞 mostra os dados, mas os medidores não mexem

O function “Separa os sensores” precisa estar com 3 saídas na aba Configuração, e o mqtt in com saída objeto JSON analisado (se vier como texto, d.temperatura fica vazio).

Aperto o botão no painel e nada acontece no Wokwi

Confiram se o tópico do mqtt out termina exatamente em /comandos/ventilador, /comandos/bomba ou /comandos/lampada, e se o On/Off Payload é ON/OFF. Testem o mesmo comando pelo cliente da HiveMQ: se lá funciona, o erro está no painel; se não, está no ESP32. Se só o LED não acende, ele pode estar ao contrário: a perna A vai no resistor e a C no GND.

Os botões ficam ligando e desligando sozinhos

A opção Pass through do switch está marcada, e o estado que volta do ESP32 vira um comando novo. Desmarquem nos três switches.

Aparecem dados estranhos, de outro grupo

Dois grupos escolheram o mesmo nome. Troquem o nome na Etapa 0 e atualizem o código do ESP32 e os tópicos do Node-RED.

O painel parou de atualizar depois de um tempo

O painel só tem dados enquanto a simulação do Wokwi está rodando. Confiram se a aba do Wokwi continua aberta e com o ▶ ativo; se precisar, rodem de novo.

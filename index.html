Etapa 0

Visão geral: o que o grupo vai construir

Até aqui, a estufa do Sr. João existia só no papel ou dentro do Node-RED. Agora ela ganha um “cérebro” de verdade: um ESP32 com sensores e atuadores, que conversa pela internet com um painel. Tudo simulado, sem precisar comprar nenhuma peça.

ESP32 no Wokwi Broker HiveMQ Painel Node-RED
Wokwi
Simulador de eletrônica no navegador. Lá montamos o circuito e rodamos o código do ESP32.
ESP32
A placa (microcontrolador) com Wi-Fi. Ela lê os sensores e liga ou desliga os atuadores.
MicroPython
A linguagem que vamos usar no ESP32: é o Python, em versão para placas pequenas.
HiveMQ
O broker MQTT, o “carteiro” na internet: recebe as mensagens do ESP32 e entrega para o Node-RED, e vice-versa. Usaremos o broker público e gratuito broker.hivemq.com.
Node-RED
Onde fica o painel (dashboard) com medidores, gráfico e botões. Pode rodar no FlowFuse (na nuvem, recomendado) ou no computador.

Primeiro passo de todos: o nome do grupo

O broker broker.hivemq.com é público: o mundo inteiro usa o mesmo. Se dois grupos usarem o mesmo tópico, um vai ligar a lâmpada do outro! Por isso, cada grupo escolhe um nome único, que entra em todos os tópicos.

Digite aqui e todos os códigos desta página se ajustam sozinhos. O nome fica salvo neste navegador; em outro computador, digite de novo, exatamente igual.
Atenção

Como o broker é público, qualquer pessoa que souber o tópico consegue ler as mensagens. Nunca envie dados pessoais, senhas ou nomes completos pelo MQTT.

    Por que o resistor?

    Ele limita a corrente que passa pelo LED. Sem ele, um LED de verdade queimaria. Os pinos do ESP32 trabalham com 3,3 V, e o resistor de 220 Ω deixa passar só o suficiente para acender.

Etapa 2 1º ponto

Programando o ESP32: Wi-Fi e MQTT

Confira se o nome do grupo foi digitado na Etapa 0: a linha GRUPO = "GRUPO_AQUI" do código abaixo tem que mostrar o nome de vocês, e não GRUPO_AQUI.

  1. Cole o código no main.py

    No Wokwi, clique na aba main.py, apague tudo e cole:

    main.py (MicroPython)
    # =========================================================
#  Estufa do Sr. João - ESP32 + Wi-Fi + MQTT (MicroPython)
# =========================================================
import network
import time
import ujson
import dht
from machine import Pin, ADC
from umqtt.simple import MQTTClient

# ---------- 1) CONFIGURAÇÕES ----------
WIFI_SSID  = "Wokwi-GUEST"        # rede Wi-Fi do simulador
WIFI_SENHA = ""                   # o Wokwi-GUEST não tem senha

BROKER    = "broker.hivemq.com"   # broker MQTT público da HiveMQ
PORTA     = 1883
GRUPO     = "GRUPO_AQUI"          # nome único do seu grupo
CLIENT_ID = "esp32-" + GRUPO

BASE            = "estufa-joao/" + GRUPO
TOPICO_SENSORES = BASE + "/sensores"     # ESP32 -> Node-RED
TOPICO_ESTADO   = BASE + "/estado"       # ESP32 -> Node-RED
TOPICO_COMANDOS = BASE + "/comandos/#"   # Node-RED -> ESP32

INTERVALO_MS = 5000               # envia os sensores a cada 5 segundos

# ---------- 2) SENSORES E ATUADORES ----------
sensor_ar = dht.DHT22(Pin(15))           # temperatura e umidade do ar
sensor_solo = ADC(Pin(34))               # potenciômetro = umidade do solo
sensor_solo.atten(ADC.ATTN_11DB)         # permite ler de 0 a 3,3 V

atuadores = {
    "ventilador": Pin(26, Pin.OUT),      # LED azul
    "bomba":      Pin(27, Pin.OUT),      # relé da bomba d'água
    "lampada":    Pin(25, Pin.OUT),      # LED amarelo
}

# ---------- 3) WI-FI ----------
def conectar_wifi():
    print("Conectando ao Wi-Fi", end="")
    wifi = network.WLAN(network.STA_IF)  # cria o objeto Wi-Fi
    wifi.active(True)                    # liga o Wi-Fi
    wifi.connect(WIFI_SSID, WIFI_SENHA)  # conecta na rede
    while not wifi.isconnected():
        print(".", end="")
        time.sleep(0.3)
    print(" conectado! IP:", wifi.ifconfig()[0])

# ---------- 4) MQTT ----------
def publicar_estado():
    estado = {}
    for nome in atuadores:
        estado[nome] = "ON" if atuadores[nome].value() == 1 else "OFF"
    cliente.publish(TOPICO_ESTADO, ujson.dumps(estado))
    print("Estado publicado:", estado)

def ao_receber_comando(topico, mensagem):
    topico = topico.decode()
    comando = mensagem.decode().strip().upper()
    nome = topico.split("/")[-1]         # ".../comandos/bomba" -> "bomba"
    print("Comando recebido:", nome, "=", comando)
    if nome in atuadores:
        if comando == "ON":
            atuadores[nome].value(1)
        elif comando == "OFF":
            atuadores[nome].value(0)
        publicar_estado()

def conectar_mqtt():
    print("Conectando ao broker", BROKER, "...")
    c = MQTTClient(CLIENT_ID, BROKER, port=PORTA, keepalive=60)  # cria o cliente
    c.set_callback(ao_receber_comando)   # função chamada quando chega comando
    c.connect()                          # conecta no broker
    c.subscribe(TOPICO_COMANDOS)         # assina os comandos dos atuadores
    print("MQTT conectado! Ouvindo:", TOPICO_COMANDOS)
    return c

# ---------- 5) PROGRAMA PRINCIPAL ----------
conectar_wifi()
cliente = conectar_mqtt()
publicar_estado()

ultimo_envio = time.ticks_add(time.ticks_ms(), -INTERVALO_MS)  # já envia na 1ª volta
while True:
    try:
        cliente.check_msg()              # chegou comando? (não trava o programa)

        if time.ticks_diff(time.ticks_ms(), ultimo_envio) >= INTERVALO_MS:
            ultimo_envio = time.ticks_ms()
            sensor_ar.measure()
            dados = {
                "temperatura": sensor_ar.temperature(),
                "umidade": sensor_ar.humidity(),
                "solo": round(sensor_solo.read() * 100 / 4095),
            }
            cliente.publish(TOPICO_SENSORES, ujson.dumps(dados))
            print("Sensores publicados:", dados)

    except OSError as erro:
        print("Conexão perdida:", erro, "- reconectando...")
        time.sleep(2)
        cliente = conectar_mqtt()

    time.sleep(0.1)

  2. Entenda as partes que valem nota

    O professor vai procurar exatamente estes comandos. Saibam apontar cada um no vídeo:

    O enunciado pedeLinha no códigoO que faz
    Criar objeto Wi-Fi com network.WLANwifi = network.WLAN(network.STA_IF)Cria o Wi-Fi no modo “estação” (o ESP32 entra numa rede, como um celular).
    Ativar com active()wifi.active(True)Liga o rádio Wi-Fi.
    Conectar com connect()wifi.connect(WIFI_SSID, WIFI_SENHA)Entra na rede Wokwi-GUEST, a rede virtual do simulador, que não tem senha.
    Cliente umqtt.simple.MQTTClientMQTTClient(CLIENT_ID, BROKER, port=PORTA, ...)Cria o “cliente” que vai conversar com o broker. O CLIENT_ID precisa ser único no broker.
    Conectar com connect()c.connect()Conecta no broker.hivemq.com, porta 1883.
    Enviar dados com publish()cliente.publish(TOPICO_SENSORES, ...)Publica os sensores em JSON a cada 5 segundos.
    Ouvir comandos com subscribe()c.subscribe(TOPICO_COMANDOS)Assina comandos/#. O # pega os três atuadores de uma vez.

    Outras peças importantes:

    • set_callback(ao_receber_comando): diz qual função rodar quando chegar uma mensagem. Ela descobre qual atuador é pelo fim do tópico e liga (ON) ou desliga (OFF).
    • check_msg(): confere se chegou comando sem travar o programa. Por isso o laço roda a cada 0,1 s, mas os sensores só são enviados a cada 5 s.
    • try / except OSError: se a conexão cair, o ESP32 reconecta sozinho em vez de parar.

Etapa 3 1º ponto

Testando o MQTT antes do painel

Antes de montar o painel, vamos conferir se o ESP32 está mesmo conversando com o broker. Para isso usamos uma página da própria HiveMQ que funciona como um “cliente MQTT” dentro do navegador: ela consegue ver o que o ESP32 manda e mandar comandos para ele.

Se algo der errado mais tarde, é este teste que mostra se o problema está no ESP32 ou no Node-RED.

Passo a passo

  1. Deixe o Wokwi rodando

    Na aba do Wokwi, a simulação precisa estar ligada (▶) e o monitor serial mostrando Sensores publicados. Não feche essa aba.

  2. Abra o cliente da HiveMQ em outra aba

    Abra uma nova aba do navegador (Ctrl + T) e acesse:

    Endereço do navegador
    https://www.hivemq.com/demos/websocket-client/

  3. Arrume o Host (área A)

    O campo Host já vem preenchido com outro endereço (como mqtt-dashboard.com). Apague e escreva:

    Host
    broker.hivemq.com

    Na Port, apague o 8000 e escreva 8884. Deixe a caixinha SSL marcada. Não mexa nos outros campos.

    Por que 8884 e não 1883 como no ESP32? O navegador não fala MQTT “puro”: ele usa WebSocket, e como a página da HiveMQ é segura (https), a conexão também precisa ser segura (SSL). A porta 8884 é a entrada segura por WebSocket. O broker é o mesmo, só a porta de entrada muda. Com a porta 8000, o navegador bloqueia e aparece o erro Connect timed out.

  4. Clique em Connect

    Clique no botão azul Connect e espere a bolinha ao lado de Connection ficar verde. O botão muda para Disconnect. Pronto, você está conectado.

  5. Assine os tópicos do grupo (área B)

    Em Subscriptions, clique em Add New Topic Subscription. Abre uma janelinha. No campo Topic, apague o que tiver e cole:

    Topic
    estufa-joao/GRUPO_AQUI/#

    Não precisa mexer em Color nem em QoS. Clique em Subscribe. O tópico aparece listado em Subscriptions.

    O # no final quer dizer “tudo o que começa com estufa-joao/GRUPO_AQUI/”: sensores, estado e comandos.

  6. Veja os dados chegando (área D)

    Clique na setinha ▾ ao lado de Messages para abrir a área. A cada 5 segundos aparece uma mensagem com o tópico .../sensores e os valores, por exemplo {"temperatura": 24.0, "umidade": 40.0, "solo": 42}.

    Mexa no DHT22 ou no potenciômetro no Wokwi e veja os números mudarem aqui. ✅ Isso prova que o publish() do ESP32 funciona.

  7. Mande um comando para o ESP32 (área C)

    Clique na setinha ▾ ao lado de Publish para abrir a área. No campo Topic, cole:

    Topic
    estufa-joao/GRUPO_AQUI/comandos/lampada

    No campo grande Message, escreva ON e clique em Publish.

    Volte para a aba do Wokwi: o LED amarelo acendeu e o monitor serial mostra Comando recebido: lampada = ON. ✅ Isso prova que o subscribe() do ESP32 funciona.

    Para apagar, publique OFF no mesmo tópico. Teste também trocando o final do tópico por ventilador (LED azul) e bomba (relé).

Não funcionou?

Aparece “Not connected” ao clicar em Subscribe

Você tentou assinar antes de conectar. Feche a janelinha, clique em Connect e só assine depois que a bolinha ficar verde.

A bolinha não fica verde

Se aparecer Connect failed … Connect timed out: confira se o Host está exatamente broker.hivemq.com, a Port 8884 e a caixinha SSL marcada. No navegador Brave, clique no leão 🦁 da barra de endereço e desligue os Shields para esse site. Se nada disso resolver, a rede está bloqueando a porta: teste roteando a internet do celular ou em casa. O Wokwi continua funcionando mesmo assim.

Conectou, mas não chega nada em Messages

O tópico assinado não bate com o do código. Compare letra por letra com a linha MQTT conectado! Ouvindo: … que aparece no começo do monitor serial do Wokwi, e com o GRUPO = "…" do main.py. Confira também se a área Messages está aberta (setinha ▾).

Publiquei ON e o LED não acendeu

Confira o tópico (tem que terminar em /comandos/lampada) e se a mensagem é só ON, sem espaços. Veja no monitor serial se aparece Comando recebido: se aparece, o problema é a ligação do LED (perna A no resistor, C no GND).

Plano B: a rede bloqueia o cliente da HiveMQ?

Este teste é só uma conferência; pode pular. Façam a mesma checagem no Node-RED do FlowFuse, que roda na nuvem e não depende da rede da sala: na Etapa 4, passo 2, o nó mqtt in ligado ao debug já mostra os dados do Wokwi na aba 🐞 (isso prova o publish()). E os botões do painel, no fim da Etapa 4, acendendo os LEDs no Wokwi provam o subscribe().

Dica para o vídeo

Este teste é ótimo para mostrar no vídeo: deixem a HiveMQ e o Wokwi lado a lado e mostrem a mensagem saindo de um lado e chegando do outro.

Etapa 4 2º ponto

Construindo o painel no Node-RED

Nesta etapa o grupo monta, no Node-RED, um painel com 3 medidores, 1 gráfico e 3 botões. Vamos montar em blocos, testando cada um antes de passar para o próximo.

Onde vamos chegar

Este é o fluxo completo, pronto. Volte a este desenho sempre que se perder:

mqtt in: sensoresSepara os sensores
gauge Temperatura
gauge Umidade do ar
gauge Umidade do solo
chart Histórico

Blocos 1 a 4: os dados do ESP32 viram medidores e gráfico.

switch Ventiladormqtt out: comandos/ventilador
switch Bomba d’águamqtt out: comandos/bomba
switch Lâmpadamqtt out: comandos/lampada

Bloco 5: os botões do painel mandam comandos para o ESP32.

mqtt in: estadoAtualiza os botõesentrada dos 3 switches

Bloco 6 (opcional): o painel mostra o estado real dos atuadores.

Opção 1 (recomendada): abrindo o Node-RED no FlowFuse

O FlowFuse é um serviço que roda o Node-RED na nuvem: ninguém instala nada, funciona em qualquer rede (inclusive a da faculdade) e o painel ganha um link para entregar. Basta uma conta por grupo; os colegas podem ser convidados depois.

Leia antes de criar a conta

O cadastro dá um teste grátis de 30 dias com um Node-RED na nuvem. Depois desse prazo, se ninguém cadastrar uma forma de pagamento, a instância é suspensa (para de rodar). Criem a conta só quando forem começar a Etapa 4, para os 30 dias cobrirem o trabalho e a correção. Os nomes dos botões podem mudar um pouco, porque o site do FlowFuse é atualizado com frequência.

  1. Abra a página de cadastro

    Acesse o endereço abaixo (é o mesmo do botão Free Trial do site do FlowFuse):

    Endereço do navegador
    https://app.flowfuse.com/account/create

  2. Crie a conta

    Preencha nome, e-mail e senha (ou entre com a conta Google, se aparecer a opção), aceite os termos e clique para criar a conta. Usem o e-mail de um integrante que todos consigam acessar, ou o institucional.

  3. Confirme o e-mail

    Abra a caixa de entrada (olhe também o spam), abra o e-mail do FlowFuse e clique no link de confirmação. Volte para o site e faça login.

  4. Crie o time (Team)

    No primeiro acesso, o FlowFuse pede para criar um time, que é o “espaço” do grupo. Dê um nome, por exemplo Estufa Grupo 3, e escolha a opção de teste grátis (Trial), se ele perguntar o tipo.

  5. Encontre ou crie a instância do Node-RED

    Uma instância é um Node-RED rodando na nuvem. Na maioria das vezes o FlowFuse já cria a primeira sozinho depois do primeiro login: ela aparece na página inicial (Home) ou em Applications.

    Se não aparecer nenhuma, crie: clique em Add Instance → dê um nome (letras minúsculas e hífen, por exemplo estufa-grupo-3) → escolha a aplicação → o tipo e a versão do Node-RED (deixe o que vier sugerido) → Next → no modelo (blueprint), escolha o em branco ou um com Dashboard, se houver → Create Instance.

  6. Espere ficar “Running”

    A instância leva de 1 a 3 minutos para ligar. Espere o status mudar para Running (rodando), com uma bolinha verde. Se ficar parado em Starting, atualize a página (F5).

  7. Clique em Open Editor

    Clique na instância e depois no botão Open Editor, no canto superior direito. O editor do Node-RED abre numa aba nova, igual ao que vocês usaram nas aulas, com a faixa vermelha no alto. O endereço é algo como https://estufa-grupo-3.flowfuse.cloud.

    Confira

    Vocês estão no editor do Node-RED: paleta de nós à esquerda, área quadriculada no meio e o botão Implementar (Deploy) no canto superior direito.

  8. Convide os colegas (opcional)

    Na página do time, procure Members (membros) e convide os e-mails dos outros integrantes. Assim todos conseguem abrir o editor com a própria conta.

Opção 2: abrindo o Node-RED no próprio computador (sem Docker)

Use esta opção só se não for usar o FlowFuse. O Node-RED é instalado direto no Windows, sem Docker e sem precisar de administrador. Duas limitações: o painel não tem link público (a entrega passa a ser o arquivo flows.json + o vídeo) e a rede da faculdade costuma bloquear os downloads do npm, então em geral só funciona em casa ou roteando a internet do celular.

  1. Abra o PowerShell

    Aperte ⊞ Windows, digite PowerShell e abra o Windows PowerShell.

  2. Veja se o Node.js já existe

    PowerShell
    PS C:\Users\aluno> node --version

    Apareceu um número como v22.x.x? Pule para o passo 4. Apareceu erro em vermelho? Siga para o passo 3.

  3. Instale o Node.js (sem administrador)

    Copie o bloco inteiro, cole no PowerShell e aperte Enter (se ficar mostrando >>, aperte Enter mais uma vez):

    PowerShell (cole tudo de uma vez)
    PS C:\Users\aluno> & {
  $ErrorActionPreference = 'Stop'
  [Net.ServicePointManager]::SecurityProtocol = 'Tls12'
  $ProgressPreference = 'SilentlyContinue'
  $lista = Invoke-RestMethod https://nodejs.org/dist/index.json
  $v = ($lista | Where-Object { $_.lts } | Select-Object -First 1).version
  Write-Host "Baixando Node.js $v ..."
  Invoke-WebRequest "https://nodejs.org/dist/$v/node-$v-win-x64.zip" -OutFile "$env:TEMP\node.zip"
  Remove-Item "$env:LOCALAPPDATA\nodejs" -Recurse -Force -ErrorAction SilentlyContinue
  Expand-Archive "$env:TEMP\node.zip" -DestinationPath $env:LOCALAPPDATA -Force
  Rename-Item "$env:LOCALAPPDATA\node-$v-win-x64" "nodejs"
  $novo = "$env:LOCALAPPDATA\nodejs;$env:APPDATA\npm"
  $userPath = [Environment]::GetEnvironmentVariable('Path','User')
  if ($userPath -notlike "*$env:LOCALAPPDATA\nodejs*") {
    [Environment]::SetEnvironmentVariable('Path', "$novo;$userPath", 'User')
  }
  $env:Path = "$novo;$env:Path"
  Write-Host "Pronto! Node.js $v instalado." -ForegroundColor Green
}

    Espere a mensagem verde Pronto! Node.js … instalado. Ele fica na pasta do seu usuário, por isso não pede senha de administrador.

    Tem administrador no computador? Também pode instalar pelo site nodejs.org: baixe a versão LTS, abra o arquivo e clique em Next até o fim. Depois feche e abra o PowerShell.

  4. Instale o Node-RED

    PowerShell
    PS C:\Users\aluno> npm.cmd install -g node-red

    Leva de 1 a 5 minutos. Linhas amarelas npm warn são só avisos. Terminou quando aparecer added … packages. Se aparecer ECONNRESET, a rede está bloqueando o npm: troque de rede ou use o FlowFuse.

    O .cmd no fim evita o bloqueio de scripts que o Windows costuma ter.

  5. Ligue o Node-RED

    PowerShell
    PS C:\Users\aluno> node-red.cmd

    Espere a linha Server now running at http://127.0.0.1:1880/. Se o Firewall perguntar, clique em Permitir acesso. Não feche esta janela: fechou, o Node-RED desliga (pode minimizar).

  6. Abra o editor no navegador

    Endereço do navegador
    http://127.0.0.1:1880

    Aparece o editor do Node-RED, com a faixa vermelha no alto.

  7. Instale o Dashboard

    Menu ☰ (canto superior direito) → Gerenciar paleta → aba Instalar → busque o pacote abaixo → Instalar → confirme.

    Nome do pacote
    @flowfuse/node-red-dashboard

  8. Desligar e ligar de novo

    Desligar: clique na janela do PowerShell e aperte Ctrl + C. Ligar outro dia: abra o PowerShell, rode node-red.cmd e abra http://127.0.0.1:1880. Não precisa instalar de novo; os fluxos ficam salvos.

Antes de montar

  1. Confira se os nós de painel estão instalados

    Na busca da paleta (à esquerda), digite gauge. Se aparecer um nó azul chamado gauge, na categoria dashboard 2, está tudo certo.

    Se não aparecer: menu ☰ (canto superior direito) → Gerenciar paleta → aba Instalar → busque @flowfuse/node-red-dashboard → Instalar.

  2. Deixe o Wokwi rodando

    Numa outra aba, a simulação do Wokwi precisa estar ligada (▶). Sem ela, não chega nenhum dado no Node-RED.

Bloco 1: receber os sensores

  1. Coloque um nó mqtt in

    Busque mqtt in na paleta (categoria rede) e arraste para a área de trabalho. Dê duplo clique nele.

  2. Cadastre o broker (só uma vez)

    No campo Servidor, escolha Adicionar novo mqtt-broker… e clique no lápis ✏️ ao lado. Preencha e clique em Adicionar:

    Broker (servidor MQTT)
    CampoO que colocar
    NomeHiveMQ público
    Servidorbroker.hivemq.com
    Porta1883
    Usar TLSdeixe desmarcado

    Daqui para frente, em todos os nós mqtt, é só escolher HiveMQ público na lista: não precisa cadastrar de novo.

  3. Configure o mqtt in

    De volta à janela do mqtt in, preencha e clique em Concluído:

    mqtt in
    CampoO que colocar
    ServidorHiveMQ público
    Tópicoestufa-joao/GRUPO_AQUI/sensores
    Saídaum objeto JSON analisado (a parsed JSON object)
    NomeSensores do ESP32

  4. Teste com um debug

    Arraste um nó debug (verde) e ligue a bolinha da direita do mqtt in na bolinha da esquerda do debug. Clique em Implementar e abra a aba 🐞 à direita.

    Confira

    Embaixo do mqtt in aparece conectado em verde, e a cada 5 segundos chega na aba 🐞 algo como {temperatura: 24, umidade: 40, solo: 42}. Se não chegar nada, não siga em frente: veja “Teste final e depuração” (Etapa 5).

Bloco 2: separar os três valores

A mensagem do ESP32 traz três números juntos, mas cada medidor só entende um número. O nó function vai separar em três saídas.

  1. Coloque um nó function

    Arraste um function (laranja) e ligue a saída do mqtt in na entrada dele. Pode deixar o debug ligado também. Dê duplo clique no function.

  2. Mude para 3 saídas

    Na aba Configuração (Setup) da janela, mude Saídas de 1 para 3. No campo Nome, escreva Separa os sensores.

  3. Cole o código

    Vá para a aba Ao receber mensagem (On Message), apague o que tiver, cole o código abaixo e clique em Concluído:

    Código do nó function
    // Chega do ESP32: { temperatura: 26.5, umidade: 55, solo: 40 }
let d = msg.payload;
return [
    { payload: d.temperatura, topic: "Temperatura (°C)" },
    { payload: d.umidade,     topic: "Umidade do ar (%)" },
    { payload: d.solo,        topic: "Umidade do solo (%)" }
];
    Confira

    O nó function agora tem 3 bolinhas do lado direito. De cima para baixo: 1 = temperatura, 2 = umidade do ar, 3 = umidade do solo.

Bloco 3: os medidores

  1. Coloque o primeiro gauge

    Busque gauge, arraste e ligue na saída 1 (a de cima) do function. Dê duplo clique.

  2. Crie o grupo “Sensores”

    No campo Group, escolha Add new ui-group… e clique no lápis ✏️. Em Name escreva Sensores e clique em Adicionar. Se aparecerem os campos Page e UI vazios, faça o mesmo neles: lápis e Adicionar, sem mudar nada.

    O grupo é a “caixinha” onde os medidores aparecem juntos no painel.

  3. Configure os três gauges

    Termine o primeiro e repita para os outros dois, ligando cada um na sua saída. Nos outros dois, em Group é só escolher Sensores, que já existe.

    Liga naLabelUnitsRange (min / max)
    Saída 1Temperatura°C0 / 50
    Saída 2Umidade do ar%0 / 100
    Saída 3Umidade do solo%0 / 100

Bloco 4: o gráfico

  1. Coloque o chart

    Busque chart e arraste. Ligue nele a saída 1 e também a saída 2 do function: uma mesma saída pode ter vários fios.

  2. Configure

    chart
    CampoO que colocar
    Groupcrie um novo: Histórico (lápis ✏️ → Adicionar)
    LabelHistórico
    TypeLine

    Cada valor vira uma linha no gráfico, com o nome que veio do código (“Temperatura (°C)”, “Umidade do ar (%)”).

  3. Teste o painel

    Clique em Implementar e abra o painel:

    • FlowFuse: na página da instância, botão Dashboard.
    • Local: abra http://127.0.0.1:1880/dashboard.
    Confira

    Aparecem os 3 medidores e o gráfico. Mexa no DHT22 e no potenciômetro do Wokwi: em até 5 segundos o painel acompanha.

Bloco 5: os botões que controlam a estufa

Agora o caminho é o contrário: o painel manda comandos para o ESP32. Cada botão (switch) se liga a um mqtt out. Faça um atuador de cada vez.

  1. Coloque o switch do ventilador

    Busque switch e use o azul, da categoria dashboard 2 (o amarelo, da categoria função, é outro nó). Arraste para um espaço vazio, abaixo do resto, e dê duplo clique:

    switch
    CampoO que colocar
    Groupcrie um novo: Controles
    LabelVentilador
    On Payloadtroque o tipo para texto (az) e escreva ON
    Off Payloadtexto OFF
    Pass throughdeixe desmarcado

    A entrada do switch fica sem fio por enquanto.

  2. Ligue um mqtt out no switch

    Busque mqtt out, arraste para a direita do switch e ligue a saída do switch nele. Duplo clique:

    mqtt out
    CampoO que colocar
    ServidorHiveMQ público
    Tópicoestufa-joao/GRUPO_AQUI/comandos/ventilador
    NomeComando ventilador

  3. Teste o ventilador

    Clique em Implementar, vá ao painel e ligue o botão Ventilador.

    Confira

    No Wokwi, o LED azul acende e o monitor serial mostra Comando recebido: ventilador = ON.

  4. Repita para a bomba e a lâmpada

    Mais dois pares switch + mqtt out, no mesmo grupo Controles. Só mudam o Label e o fim do tópico:

    Switch: Labelmqtt out: TópicoO que acende no Wokwi
    Bomba d’águaestufa-joao/GRUPO_AQUI/comandos/bombaO LED do relé
    Lâmpadaestufa-joao/GRUPO_AQUI/comandos/lampadaO LED amarelo

    Dica: selecione o par já pronto do ventilador, copie (Ctrl + C), cole (Ctrl + V) e só troque o Label e o tópico.

Neste ponto o painel já vale os pontos da avaliação

Medidores, gráfico e botões controlando os atuadores. O Bloco 6 é uma melhoria.

Bloco 6 (opcional): botões mostrando o estado real

Se o ESP32 reiniciar, ou alguém mandar um comando por fora (pelo cliente da HiveMQ, por exemplo), o botão do painel fica mostrando a posição errada. Para corrigir, o painel “escuta” o tópico estado, que o ESP32 publica toda vez que um atuador muda.

  1. Coloque outro mqtt in

    mqtt in
    CampoO que colocar
    ServidorHiveMQ público
    Tópicoestufa-joao/GRUPO_AQUI/estado
    Saídaum objeto JSON analisado
    NomeEstado dos atuadores

  2. Coloque um function com 3 saídas

    Ligue depois do mqtt in. Na aba Configuração, Saídas = 3; nome Atualiza os botões; na aba Ao receber mensagem, cole:

    Código do nó function
    // Chega do ESP32: { ventilador: "ON", bomba: "OFF", lampada: "OFF" }
// Atualiza os botões do painel com o estado REAL dos atuadores
let e = msg.payload;
return [
    { payload: e.ventilador },
    { payload: e.bomba },
    { payload: e.lampada }
];

  3. Ligue as saídas na ENTRADA dos switches

    Saída 1 → bolinha da esquerda do switch Ventilador; saída 2 → switch Bomba d’água; saída 3 → switch Lâmpada. Clique em Implementar.

    Confira

    Mande ON pelo cliente da HiveMQ (Etapa 3): o botão do painel muda sozinho. Como o Pass through está desmarcado, o switch só muda de posição e não manda o comando de novo, por isso não vira um “loop”.

Etapa 5

Teste final e depuração

Com o Wokwi rodando numa aba e o painel aberto em outra (de preferência lado a lado), confiram um por um:

  1. Sensores no painel

    Mudem a temperatura no DHT22 e girem o potenciômetro. Em até 5 segundos, os medidores e o gráfico acompanham.

  2. Botões no ESP32

    Liguem e desliguem cada botão do painel. O LED azul (ventilador), o relé (bomba) e o LED amarelo (lâmpada) obedecem, e o monitor serial mostra o Comando recebido.

  3. Estado de volta no painel

    Mandem ON pelo cliente da HiveMQ (Etapa 3). O botão correspondente no painel deve mudar sozinho.

Deu problema? Procure o sintoma

O monitor serial fica só em “Conectando ao Wi-Fi.....”

Confiram se está escrito exatamente Wokwi-GUEST (com letras maiúsculas e o hífen) e a senha vazia "". Parem e rodem de novo a simulação.

“ImportError: no module named 'umqtt'” ou erro logo na primeira linha

O projeto não é MicroPython. Criem um novo pelo link da Etapa 1 e colem o circuito e o código nele.

“MQTTException: 2” ou o ESP32 fica reconectando sem parar

O CLIENT_ID já está em uso. Isso acontece quando a mesma simulação está aberta em duas abas ou dois computadores do grupo: o broker derruba um para aceitar o outro. Deixem o Wokwi rodando em um só lugar. Se ainda assim continuar, troquem o nome do grupo por algo mais único.

“OSError: [Errno 116] ETIMEDOUT” na leitura do DHT22

O fio de dados do DHT22 (SDA) não está no pino 15, ou falta VCC/GND. Confiram a tabela de ligações.

Os dados aparecem no cliente da HiveMQ, mas não no Node-RED

O problema está no Node-RED: (1) o tópico do mqtt in está diferente, letra por letra, do que o ESP32 usa; (2) o servidor não é broker.hivemq.com porta 1883; (3) faltou clicar em Implementar. Olhem se embaixo do mqtt in aparece conectado.

A aba 🐞 mostra os dados, mas os medidores não mexem

O function “Separa os sensores” precisa estar com 3 saídas na aba Configuração, e o mqtt in com saída objeto JSON analisado (se vier como texto, d.temperatura fica vazio).

Aperto o botão no painel e nada acontece no Wokwi

Confiram se o tópico do mqtt out termina exatamente em /comandos/ventilador, /comandos/bomba ou /comandos/lampada, e se o On/Off Payload é ON/OFF. Testem o mesmo comando pelo cliente da HiveMQ: se lá funciona, o erro está no painel; se não, está no ESP32. Se só o LED não acende, ele pode estar ao contrário: a perna A vai no resistor e a C no GND.

Os botões ficam ligando e desligando sozinhos

A opção Pass through do switch está marcada, e o estado que volta do ESP32 vira um comando novo. Desmarquem nos três switches.

Aparecem dados estranhos, de outro grupo

Dois grupos escolheram o mesmo nome. Troquem o nome na Etapa 0 e atualizem o código do ESP32 e os tópicos do Node-RED.

O painel parou de atualizar depois de um tempo

O painel só tem dados enquanto a simulação do Wokwi está rodando. Confiram se a aba do Wokwi continua aberta e com o ▶ ativo; se precisar, rodem de novo.

Não apaguem nem parem a instância do FlowFuse depois da entrega.
